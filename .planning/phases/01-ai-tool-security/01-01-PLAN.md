# Phase 01 — AI Tool Security Hardening

Security review findings from `ai-tool-safety-2026-05-03` addressed in full.

## Source

`.planning/reviews/ai-tool-safety-2026-05-03/REVIEW.md` — deep review of 17 files,
13 findings (4 critical, 5 warning, 4 info).

## Completed Tasks

### CR-01 — Client Message Role Injection ✅
**File:** `app/api/chat/route.ts`
`normalizeIncomingMessages()` strips any role not in `['user', 'assistant']`.
Parts validated to text-only, max 20k chars each.

### CR-02 — RAG Context Prompt Injection ✅
**File:** `app/api/chat/route.ts`
RAG context injected as a `user` message (not system) with explicit UNTRUSTED
prefix and directive to ignore instructions inside snippets.

### CR-03 — Destructive Confirmation Model-Satisfiable ✅
**File:** `lib/ai/tools/repository/delete-repository.ts`
Hard-gate: last user message must equal exact repo name. Model cannot self-confirm.

### CR-04 — Path Traversal in File Reader ✅
**File:** `lib/ai/tools/read-file.ts`
Uses `path.relative(realProjectRoot, realAbsolutePath)` — rejects paths starting
with `..` or absolute paths.

### WR-02 — Tool Error Stack Trace Leak ✅
**File:** `lib/ai/create-tool.ts`
Returns `error.message` only. No `error.stack` or `error.response.data` in tool result.

### WR-04 — Blocked Messages Still Persisted ✅
**File:** `app/api/chat/route.ts`
`userMessageSavePromise` moved to after `await safetyPromise` resolves.
Blocked messages never reach the DB.

### WR-03 — Assistant Message Redaction Skipped ✅
**File:** `lib/services/messages.ts`
Removed `role === 'user'` guard — both user and assistant messages redacted
before storage.

### WR-05 — RAG Indexer Stores Secret Files ✅
**File:** `lib/rag/indexer.ts`
`SECRET_PATH_PATTERNS` denylist added. Paths matching `.env`, `secrets.*`,
`credentials.*`, `private_key`, `.pem`, `id_rsa`, `.p12`, `.pfx` are skipped
before file extension filtering.

## Info Items (Accepted, No Action)

- **IN-01**: Inconsistent tool result shapes — low risk, not blocking
- **IN-02**: Dev tool logging — already gated to `NODE_ENV === 'development'`
- **IN-03**: Safety guard scans last message only — acceptable for current threat model
- **IN-04**: Tool gating in prompts only — partially mitigated by CR-03 hard-gate pattern

## WR-01 Status (Accepted Risk)

Safety guard intentionally fail-open with 800ms timeout. Dummy API key documented
as intentional (free tier). Accepted by team — GitHub management ops should not
block on safety service outage.
